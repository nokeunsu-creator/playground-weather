# 보안 점검 보고서 (2026-11-15)

대상: 놀이터 날씨 앱(Capacitor Android + React), 데이터 파이프라인(GitHub Actions), 데이터 호스팅(GitHub Pages).
방법: 정적 코드 검토, APK 매니페스트·번들 검사(aapt2, 번들 내 비밀값 탐색), 의존성 취약점 검사(npm audit), 브라우저 동적 테스트(Playwright, CSP 위반·콘솔 오류 수집), 공개 데이터 엔드포인트 헤더 검사.

## 1. 공격 표면 요약
- 앱은 서버·계정·로그인이 없다. 네트워크는 GitHub Pages(JSON 읽기), 지도 타일, 지도 앱 링크, AdMob SDK(네이티브)뿐이다.
- 사용자 데이터는 기기 안의 설정(아이 나이대, 즐겨찾기, 마지막 위치)뿐이며 외부 전송이 없다.
- 비밀 키(data.go.kr)는 GitHub Actions Secrets 에만 있고 앱 번들에는 없다(번들 검사로 확인).
- 파이프라인은 외부 HTML/JSON을 읽기만 하고 코드로 실행하지 않는다(정규식·인덱스 파싱, eval 없음).

## 2. 발견 사항과 조치

| # | 심각도 | 발견 | 조치 |
|---|---|---|---|
| 1 | 중 | `csv-parse` 프로토타입 오염 취약점(npm audit moderate). 실제로는 코드에서 쓰지 않는 패키지 | 패키지 제거(iconv-lite 도 미사용이라 함께 제거) → audit 0건 |
| 2 | 중 | `android:allowBackup="true"` 기본값. 루팅·ADB 백업으로 로컬 설정 추출 가능 | `allowBackup=false` + `dataExtractionRules`(클라우드 백업·기기 이전 전부 제외) |
| 3 | 중 | WebView 에 CSP 없음. 데이터 파일이 변조되거나 XSS 가 생기면 외부 스크립트·전송이 자유로움 | `index.html` 에 CSP 추가: 스크립트·스타일은 자체 번들만, 연결은 GitHub Pages 와 브이월드만, 이미지는 지도 타일만, frame/object 차단. Capacitor 브리지가 인라인 스크립트라 `'unsafe-inline'` 은 불가피 |
| 4 | 하 | 디버그 APK 는 `debuggable=true` | 출시는 서명된 release 빌드(AAB)로 하고 디버그 APK 는 배포하지 않음(출시 체크리스트에 기록) |
| 5 | 하 | 브이월드 지도 타일 키는 앱 번들에 들어가므로 추출 가능 | 지오코딩 키(서버용)와 타일 키(앱용)를 분리 발급하고, 타일 키는 브이월드 콘솔에서 앱 패키지명/호출 한도를 제한. 유출돼도 타일 조회 한도 소진 이상의 피해 없음 |
| 6 | 하 | GitHub Actions 가 `actions/checkout@v4` 등 태그로 고정 | 공식 액션이라 위험은 낮음. 필요 시 커밋 SHA 고정 |
| 7 | 정보 | LAN 테스트용 미리보기 서버(0.0.0.0:4174) | 테스트 후 종료 |

검토했으나 문제 없음: 위험한 DOM 싱크(innerHTML/eval) 없음, Leaflet 마커 HTML 은 상수만 사용, React 가 모든 데이터 문자열을 이스케이프, 외부 링크는 `encodeURIComponent` 적용, 모든 엔드포인트 HTTPS, 평문 통신 비허용(기본), exported 컴포넌트는 런처 액티비티뿐, FileProvider 비공개, 권한 최소(위치·알림·정확한 알람·광고ID), `.env` 와 키스토어는 git 제외, git 기록에 키 없음.

## 5. 남은 권고
1. 출시 전 release 서명 빌드(AAB)로 전환하고 키스토어는 저장소 밖에 보관.
2. 브이월드 키 2개 분리(앱 타일용·파이프라인 지오코딩용).
3. GitHub 저장소에 `gh-pages`·`main` 브랜치 보호 규칙(강제 푸시 금지).
4. AdMob 실제 ID 적용 후 테스트 기기 등록, 광고 정책(아동 대상 아님) 설정 확인.
